## 1. Objetivo

Construir el motor que compara una medición con el **historial personal** del astronauta: mediana, cuánto se aleja de ella y qué registros usó. **Sin diagnósticos ni umbrales.** Es el punto 2 del recorrido de la demo.

**Regla de independencia (T-304):** los casos del §5 los definió Bruno **antes** de implementar. Se trabaja en **dos fases**:

1. **Fase 1:** se escriben las pruebas **exactamente** como dice el §5, sin implementar el motor. Bruno las revisa.
2. **Fase 2:** se implementa el motor **sin modificar esas pruebas**. Si una prueba parece incorrecta, se detiene y se pregunta a Bruno.

## 2. Alcance permitido

- Solo `packages/health-engine/`: `src/`, sus pruebas y su `package.json`.
- En `package.json` se agrega la dependencia de workspace `"@astra/contracts": "*"`, para usar el tipo `Measurement`. **No** es una dependencia externa. Ninguna otra.
- **No tocar:** `packages/contracts/`, `apps/`.
- El motor es **puro**:
  - sin React, NestJS, Dexie ni red;
  - no lee el reloj del sistema;
  - **no modifica** sus entradas;
  - **no redondea**.

## 3. API del motor (contrato definido por Bruno)

```ts
export const PERSONAL_RULES_VERSION = "personal-1";

export function evaluatePersonal(target: Measurement, history: readonly Measurement[]): PersonalEvaluation;
export function evaluateClinical(target: Measurement): ClinicalEvaluation;

export type PersonalStatus = "COMPUTED" | "INSUFFICIENT_DATA" | "NOT_APPLICABLE";

export interface ComponentResult {
  component: "value" | "systolic" | "diastolic";
  value: number;               // valor de la medición evaluada
  median: number;
  absoluteDifference: number;  // value − median (con signo)
  percentDifference: number | null;
  percentNullReason?: "MEDIAN_IS_ZERO";
}

export interface PersonalEvaluation {
  status: PersonalStatus;
  components: ComponentResult[];     // vacío salvo con COMPUTED; orden [systolic, diastolic] o [value]
  usedRecordIds: string[];           // registros comparables usados, del más antiguo al más reciente
  usedCount: number;                 // = usedRecordIds.length
  criteria: {
    sameAstronaut: true; sameIndicator: true; sameUnit: true; sameContext: true;
    strictlyBeforeCapturedAtSim: true; maxRecords: 7; minRecords: 3;
    tieBreak: ["capturedAtSim", "capturedAtReal", "id"];
  };
  rulesVersion: "personal-1";
  engineVersion: string;             // = ENGINE_VERSION
}

export interface ClinicalEvaluation {
  status: "CLINICAL_RULES_NOT_AVAILABLE";
  rulesVersion: "none";
}
```

**Reglas** (ARCHITECTURE §8 y T-005 §4):

1. **Comparable:** mismo `astronautId`, `indicator`, `unit` y `context`, con `capturedAtSim` **estrictamente anterior** al del objetivo. La propia medición (mismo `id`) nunca cuenta.
2. **Orden:** ascendente por `capturedAtSim`, después `capturedAtReal`, después `id` (comparación de texto). Se toman los **7 últimos**.
3. **Resultado según cuántos hay:**
   - menos de 3 → `INSUFFICIENT_DATA`, con `usedRecordIds` = los que hubo;
   - estado de ánimo (`MOOD`) → siempre `NOT_APPLICABLE` y `components` vacío, con `usedRecordIds` = sus comparables (hasta 7).
4. **Mediana:** con número par, el promedio de los dos centrales.
5. **Porcentaje:** `(value − median) / median × 100`. Si la mediana es 0 → `null` con `percentNullReason: "MEDIAN_IS_ZERO"`.
6. **Presión arterial:** cada componente por separado.

## 4. Datos de las pruebas

- Ayudante de prueba: `m(nn, overrides)` crea una medición válida (pasada por `MeasurementSchema.parse`) con:
  - `id = "c0000000-0000-4000-8000-0000000000NN"`,
  - `astronautId: "sam"`, `HEART_RATE`, `bpm`, `AT_REST` y `origin: "MANUAL"`,
  - `clockVersion: 1`, `envProfile: "MARS_TRANSIT"` y `envVersion: 1`,
  - `capturedAtReal = capturedAtSim` salvo que el caso diga otra cosa.
- **Día N** = `2026-10-NNT08:00:00.000Z`. El **objetivo** se captura el **día 20** y su `id` es `…0000000000ff`, salvo que se indique otra cosa.
- Para decimales se usa `toBeCloseTo(esperado, 10)`.
- Los casos se escriben en `src/personal.test.ts` y `src/clinical.test.ts`.

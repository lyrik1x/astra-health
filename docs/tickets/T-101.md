# T-101 — Crear monorepositorio

**Proyecto:** ASTRA HEALTH · **Responsable:** Bruno · **Fase:** MVP · **Fecha:** 14 nov 2026
**Fuente:** TASKS.md T-101, ARCHITECTURE.md §2, §3, §4, §12, §14 y AGENTS.md (completo).
**Dependencias:** T-001 (reglas) y T-002 (herramientas). T-002 está lista en la laptop de Bruno; T-001 está en curso y no afecta la estructura base.

## 1. Objetivo

Dejar el esqueleto del monorepositorio compilando, arrancando y con pruebas, para que T-102 (contratos), T-103 (interfaz) y T-104 (API) empiecen sobre una base verificada.

## 2. Alcance permitido

Raíz del repositorio, `apps/web`, `apps/api`, `packages/contracts`, `packages/health-engine`. **No** se toca `docs/`, `AGENTS.md` ni `CLAUDE.md`.

**Fuera de este ticket:** entidades y esquemas del MVP (T-102), módulos `measurements`, `crew`, `communications`, `incidents` y `missions` (T-104 y siguientes), Dexie, service worker y `vite-plugin-pwa` (T-202/T-206), Tailwind, react-i18next y Recharts (T-103/T-605), seed de datos (T-105).

## 3. Criterios de aceptación (TASKS.md T-101)

1. Instalación y ejecución reproducibles en la laptop: `npm install` en la raíz y los scripts de §5 funcionan desde cero.
2. `apps/web` y `apps/api` importan **un tipo, un esquema Zod y una función** de `packages/contracts`, y **una función** de `packages/health-engine`. Se demuestra con código que se ejecuta (no solo con un `import` sin uso).
3. `apps/api` compila y arranca con NestJS. Prisma genera su cliente y aplica una **migración inicial** sobre SQLite dentro del workspace. El módulo `health` responde en `GET /api/health`.
4. `apps/web` compila con `vite build`, se sirve con `vite preview` y muestra en pantalla la respuesta de `/api/health`.
5. CORS acepta solo los orígenes de desarrollo y de `vite preview`, configurados por variable de entorno.
6. `.gitignore` y las variables de entorno excluyen secretos y el archivo de SQLite del repositorio.

Pruebas asociadas: QA-702, QA-705, QA-706 (`docs/TEST_PLAN.md`). Leerlas antes de planificar.

## 4. Supuestos propuestos (Bruno los aprueba en el plan)

- **S1 — Función de `contracts`:** la función de prueba es directamente `computeSimNow(clock, realNow)`, única implementación de `simNow = simEpoch + (realNow − realEpoch) × factor` (ARCHITECTURE §10.3), con dos pruebas Vitest: anclaje (`realNow = realEpoch` da `simEpoch`) y avance (10 s reales con factor 60 = 10 min simulados). Adelanta el paso 2 de D-23 sin cambiar contratos. El esquema Zod de prueba es el de `MissionClock` (`simEpoch`, `realEpoch`, `factor`, `clockVersion`) según ARCHITECTURE §5.1. T-102 puede ajustarlo.
- **S2 — Función de `health-engine`:** una función trivial con su prueba (por ejemplo, `engineVersion()`). Sin lógica del motor (T-302).
- **S3 — Migración inicial:** una tabla `MissionClock` con los campos de S1. Sin seed. El esquema completo llega con T-104.
- **S4 — Ramas:** T-101 se confirma directamente en `main` como commit inicial. A partir de T-102, una rama por ticket.

## 5. Configuración obligatoria

**Versiones:** Node 26 (misma versión mayor en todas las laptops). Declarar `"engines": { "node": ">=26 <27" }` en el `package.json` raíz. Versiones estables actuales de cada dependencia.

**Puertos:** API 3000 · Vite desarrollo 5173 · `vite preview` 4173.

**Variables de entorno** (con `.env.example` sin secretos):
- API: `PORT=3000`, `DATABASE_URL` (SQLite dentro de `apps/api`), `CORS_ORIGINS=http://localhost:5173,http://localhost:4173`.
- Web: `VITE_API_URL=http://localhost:3000`.

**Scripts del `package.json` raíz** (nombres fijos; las guías de verificación dependen de ellos):

| Script | Qué hace |
|---|---|
| `npm run build` | Compila los cuatro workspaces en orden: contracts → health-engine → api → web |
| `npm test` | Ejecuta todas las pruebas de todos los workspaces |
| `npm run db:setup` | Aplica las migraciones de Prisma. **Repetible**: correrlo dos veces no falla |
| `npm run db:reset` | Borra la base de SQLite de desarrollo y la recrea desde las migraciones |
| `npm run start:api` | Arranca la API compilada en el puerto 3000 |
| `npm run dev:web` | Vite en modo desarrollo (5173) |
| `npm run preview:web` | Sirve el build de `apps/web` con `vite preview` (4173) |

## 1. Objetivo

Poder **ensayar la demo muchas veces** y dejar todo como al principio con un solo paso:

1. La base del servidor vuelve al seed.
2. El reloj se reinicia.
3. Se borra la base local de la nave.
4. La nave vuelve a descargar su historial.

Sin tocar a mano ninguna base de datos.

## 3. Parte A — `POST /api/demo/reset`

1. **Variable de entorno `DEMO_RESET_ENABLED`:**
   - En `loadConfig`, **opcional**: solo `"true"` la activa, y cualquier otro valor o su ausencia la deja **desactivada**.
   - Es la única variable opcional; dejarlo comentado en el código.
   - En `.env.example`, agregar `DEMO_RESET_ENABLED=true`.
2. **Desactivada → la ruta responde 404** (QA-707), con el formato de error normal, como si no existiera.
3. **Activada:**
   - Exige `X-Demo-Role` (cualquiera de los dos roles); sin cabecera → 400, como las demás rutas.
   - **Borra los datos de la demo** dentro de **una transacción de Prisma**, en este orden por las claves foráneas:
     1. `Measurement`, `IncidentEvent`, `Message`;
     2. después `Transmission`;
     3. después `Astronaut`, `EnvironmentProfile` y `MissionClock`.
   - Después llama a `seedDatabase(prisma, now)` con `now` del `NowProvider`. Así el reloj queda con `simEpoch = realEpoch = now`, factor 60 y `clockVersion` 1.
   - Responde **200** con `{ clock }`, validado con `DemoResetResponseSchema`.
4. Es la **única** función del servidor que borra datos. Dejarlo comentado y limitado a esta ruta.

## 4. Parte B — `resetShipDemo()` (cliente, sin interfaz)

`resetShipDemo({ api, deleteDatabase, reload })`, con las dependencias inyectadas para poder probarlo:

1. Llama a `POST /api/demo/reset` con `apiFetch`. Si falla, **se detiene sin borrar nada local** y lanza un error claro.
2. Cierra y borra la base de la nave: `closeShipDb()` y luego `Dexie.delete(SHIP_DB_NAME)`. Solo existe en el rol Nave: con el rol Tierra, se omite este paso.
3. Recarga la página (`location.reload()`). Al abrir de nuevo, la sincronización automática (T-204) vuelve a descargar el historial (QA-112).

## 5. Pruebas

- Sin la variable → 404. Con `DEMO_RESET_ENABLED=false` → 404.
- Activada y sin cabecera → 400.

  - se agrega una medición con `POST /api/sync/batch` y se cambia el factor del reloj;

- Si la API falla → no borra ni recarga.

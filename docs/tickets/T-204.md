## 1. Objetivo

Conectar las piezas que ya existen para que el recorrido **se vea funcionando en el navegador**:

1. La nave descarga su historial.
2. Sam captura una medición, que **se guarda en el dispositivo**.
3. Se envía sola cuando hay enlace.
4. El dashboard muestra cada medición con su estado: guardado, en cola, confirmado, en tránsito, entregado o error.

Es la primera vez que la demo funciona de punta a punta en la nave.

## 3. Criterios de aceptación

1. **Sincronización automática, solo en Nave:**
   - Al abrir la app como Nave y **con enlace**, se llama a `syncOnce()` una vez. Esto descarga la tripulación, el reloj y el historial (QA-112).
   - Después se llama otra vez:
     - con el evento `online` del navegador,
     - cada **5 s** mientras `navigator.onLine` sea `true`,
     - justo después de guardar una medición.
   - **No se encimen ciclos:** si hay uno en curso, se salta el siguiente. El *lock* ya lo protege, pero así no se acumulan llamadas.
   - En **Tierra** no se monta nada de esto, y nunca se abre Dexie (`getShipDb` lanzaría `ShipDbForbiddenError`).
   - Si `syncOnce()` falla, se registra en la consola y **no rompe la página**.
2. **Indicador de enlace** (solo Nave): muestra **Online** u **Offline** según `navigator.onLine` y los eventos `online` y `offline`. Sin enlace usa el `StatusBadge` `OFFLINE`. Una pérdida de enlace **nunca** se muestra como "en tránsito" (QA-406).
3. **El formulario usa los datos locales** (se retira lo simulado):
   - La tripulación sale de `getLocalCrew()` y el reloj y el perfil de `getLocalMissionConfig()`.
   - Si alguno es `null` porque nunca hubo conexión: mensaje neutral ("Connect once to download mission data") y el botón de captura desactivado.
   - Se sigue usando `buildMeasurement` y la validación de T-201. El `realNow` de la captura es **el mismo** que se pasa a `saveMeasurementLocal(measurement, realNow)`.
   - Al guardar: `StatusBadge` **`SAVED_LOCAL`** ("Saved on device") y después se dispara `syncOnce()` si hay enlace.
   - Se manejan los errores: `LocalRecordExistsError` y cualquier otro, con un mensaje neutral, sin perder lo escrito en el formulario.
   - Se **borran** `dev-fixtures.ts`, `measurement-store.ts` y sus pruebas, y la nota de "fictional development data".
4. **Dashboard (T-204):**
   - Selector de astronauta con la tripulación local. Por defecto, el primero.
   - Lista de sus mediciones de `listMeasurementsLocal()`, **la más reciente primero**. Cada una muestra:
     - indicador,
     - valor con su unidad, redondeado según T-005 §3.1 (la presión como `120/80`),
     - contexto,
     - momento de captura **simulado** (y el real en texto pequeño),
     - estado.
   - El estado sale de una **función pura** `displayStatusFor(record, config, realNow)`:
     - `SAVED_LOCAL`, `PENDING_SYNC` o `SYNC_ERROR` (con el código de `lastError`), tal cual.
     - `CONFIRMED` → **dos** badges: "Confirmed by channel" + `IN_TRANSIT` o `DELIVERED`. El transporte se calcula con `computeSimNow(config.clock, realNow)` contra `transmission.deliverAt`. **Confirmado no es entregado.**
   - La lista se vuelve a leer cada **2 s**, para que el cambio de estado se vea sin recargar.
   - Se conserva el botón "Record a measurement" y la leyenda.
5. **Nada clínico:** ni colores según el valor, ni rangos, ni evaluación (eso es T-303). Todos los textos con claves de i18n. Se puede usar con teclado.

## 4. Pruebas (Vitest)

- `displayStatusFor`:
  - cada estado local (`SAVED_LOCAL`, `PENDING_SYNC` y `SYNC_ERROR` con su código);
  - `CONFIRMED` antes de `deliverAt` → `IN_TRANSIT`;
  - en `deliverAt` o después → `DELIVERED`.
- Formato del valor: decimales por indicador y presión `120/80`.
- El arranque de la sincronización (por ejemplo, `createShipSyncRunner({ syncOnce, isOnline, setInterval })`, con dependencias inyectadas):
  - llama al inicio si hay enlace;
  - no encima ciclos;
  - reacciona a `online`;
  - no llama sin enlace.
- `keys.test.ts` y `no-direct-fetch.test.ts` siguen en verde. Las **334** pruebas actuales, menos las de los archivos borrados, siguen en verde.

## 5. Prueba manual (la más importante: es el recorrido de la demo)

Con `npm run build`, `npm run start:api` y `npm run preview:web`. Si la base ya tiene pruebas viejas, antes se puede correr `npm run db:reset` y luego `npm run db:setup`.

1. Abrir `?role=ship` → **Dashboard**. Deben aparecer las **6 mediciones de Sam** del seed (más 2 de temperatura), con "Confirmed" y **"Delivered"**.
2. **Record measurement:** Sam, heart rate, `80`. Aparece "Saved on device". En el Dashboard pasa a **"Confirmed" + "In transit"** en pocos segundos.
3. Esperar **2 minutos reales** (120 min simulados): cambia a **"Delivered"** sin recargar.
4. **Sin enlace:** F12 → Red → **Offline**. El indicador dice **Offline**. Capturar otra medición: queda en **"Saved on device"** o **"Queued"**, **nunca** "In transit". Quitar Offline → se confirma sola.
5. Tierra: en PowerShell, `Invoke-RestMethod "http://localhost:3000/api/measurements?astronautId=sam" -Headers @{ "X-Demo-Role" = "EARTH" }`. La medición nueva **no** aparece antes de los 2 minutos y **sí** después.
6. Abrir `?role=earth`: no debe haber errores en la consola ni base `astra-health` nueva en IndexedDB.

📸 Capturas: el dashboard con Delivered, la medición en tránsito y el estado sin conexión.

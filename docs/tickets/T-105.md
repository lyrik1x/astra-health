## 3. Criterios de aceptación

1. **`GET /api/crew`** (T-005 §5.1):
   - Responde `{ crew: Astronaut[] }` y la respuesta valida contra `CrewResponseSchema` de `@astra/contracts`.
   - Exige `X-Demo-Role` como las demás rutas: sin la cabecera, o con un valor inválido, responde 400 `MISSING_OR_INVALID_ROLE`. Eso ya lo hace la infraestructura de T-104; solo hay que comprobarlo.
   - Funciona igual con `SHIP` y con `EARTH`. Orden por `id`.
2. **Función del seed reutilizable:** `seedDatabase(prisma, realNow: Date)` en `src/seed/`. T-706 (reinicio de la demo) la va a reutilizar, así que **no** debe leer el reloj del sistema por dentro: recibe `realNow`.
3. **Qué crea el seed** (T-005 §7 y §8), **solo si no existe**:
   - **Reloj** (fila `id = 1`): `factor = 60`, `clockVersion = 1`, `simEpoch = realEpoch = realNow`. Si ya existe, **no se toca**.
   - **Perfil:** `MARS_TRANSIT`, `version = 1`, `oneWayDelayMinutesSim = 120`, `delaySource = "SIMULATED"`, `description = "Simulated one-way delay (no verified source yet)"`. Debe validar contra `EnvironmentProfileSchema`.
   - **Tripulación:** `sam` → "Sam" y `alex` → "Alex".
   - **Mediciones**, con UUID y fechas **fijos** (tabla de §4).
4. **Cada medición del seed:**
   - Su payload valida con `MeasurementSchema`. Se parsea primero, y `payloadCanonical = canonicalJson(parsed)` usa la función que ya existe en `src/common/canonical-json.ts`.
   - Campos comunes: `origin: "MANUAL"`, `context: "AT_REST"`, `clockVersion: 1`, `envProfile: "MARS_TRANSIT"`, `envVersion: 1`, `capturedAtReal = capturedAtSim`.
   - Tiene su `Transmission`: `direction: "SHIP_TO_EARTH"`, `contentKind: "MEASUREMENT"`, `contentId` = id de la medición, `acceptedAtSim = acceptedAtReal = capturedAtSim + 1 minuto`, `deliverAt = acceptedAtSim + 120 minutos`, `envProfile: "MARS_TRANSIT"`, `envVersion: 1`.
   - La medición y su transmisión se crean **en la misma transacción de Prisma**.
   - Todas quedan con `deliverAt` en el pasado simulado, así que Tierra ya las ve como `DELIVERED`.
5. **Repetible (M-4):** correr el seed dos veces deja exactamente los mismos registros. Nunca sobrescribe ni duplica.
6. **Comandos que usa todo el equipo:**
   - `npm run db:seed -w @astra/api` corre el seed contra la base de `.env`.
   - `npm run db:setup` (raíz) aplica las migraciones **y después** corre el seed.
   - Tiene que funcionar **desde cero**: con `apps/api/dev.db` borrado y sin carpetas `dist`, después de `npm ci`, `npm run db:setup` debe terminar bien. Si para eso hace falta compilar `@astra/contracts` primero, el script lo hace.
7. **Resultado visible con la API corriendo** (`npm run start:api`):
   - `GET /api/crew` con `X-Demo-Role: SHIP` → Sam y Alex.
   - `GET /api/measurements?astronautId=sam` con `X-Demo-Role: EARTH` → **8** elementos, todos `DELIVERED`.
   - `GET /api/measurements?astronautId=alex` con `X-Demo-Role: EARTH` → **3** elementos.
   - Ya no aparece el 503.
